# 効果音ポン出しくんEX 仕様書

- 文書版: 0.1
- 想定初期版: EX v1.0
- 仕様上の参考: [効果音ポンだしくん](https://www.vector.co.jp/soft/winnt/art/se499320.html) v1.7.0 (2022-12-12)
- 対象用途: 学校演劇・舞台音響でのBGM / 効果音のポン出し

---

## 1. 目的

「効果音ポンだしくん v1.7.0」の主要機能と操作感を参考にしつつ、舞台本番で問題になりやすい以下の点を個人的に使いやすくしたソフトを独立実装する。

本ソフトは元ソフトの公式アップデートや公式後継版ではない。元ソフトのソースコード、バイナリ、画像、音声、その他の配布物を含めず、それらに実行時依存しない。

1. 音源操作用の子ウィンドウや各コントロールにフォーカスがあると、キーアサインが効かなくなる問題を解消する。
2. 全体的に小さいUIを大型化し、本番中でも視認・操作しやすくする。
3. 「全停止」をメニューやショートカットだけでなく、常時見えるGUIボタンから即座に実行できるようにする。
4. 独自バイナリのプロジェクト形式を廃止し、人間が直接読めるJSON形式にする。
5. 長期間ネットワーク接続されていない古いWindows PCでも、追加インストールなしで動作できる自己完結型アプリにする。

本ソフトでは、見た目の豪華さよりも「押したら確実に鳴る・止まる」「本番中に操作不能にならない」ことを最優先する。

## 2. 想定動作環境

### 2.1 基準環境

最低限、以下程度のPCで快適に使用できることを目標とする。

- OS: Windows 10 64bit（21H2程度を含む古めの環境）
- CPU: Intel Core i5 第3世代程度
- RAM: 8 GB
- GPU: 内蔵GPUで可
- ストレージ: HDD / SSDの両方を想定
- ネットワーク: 接続なしを前提

### 2.2 配布・実行条件

- ZIPを展開してEXEを起動するだけで使用可能であること。
- .NET Runtime等の事前インストールを要求しないこと。
- 音声デコーダなど必要な再配布可能コンポーネントは同梱すること。
- Microsoft Store、Windows Update、Web API、オンライン認証を必要としないこと。
- 管理者権限を必要としないこと。
- レジストリへの登録を必須としないこと。
- 自動アップデート確認を行わないこと。
- アンインストールは原則としてフォルダ削除のみで完了すること。
- 別PCへの移行はアプリ／プロジェクトフォルダのコピーで行えること。

## 3. 互換方針

### 3.1 参考とする機能

効果音ポンだしくん v1.7.0を仕様上の参考とし、その主要機能に相当する機能をEXでも提供する。

ただし、UIをピクセル単位で再現する必要はない。機能・操作結果が同等以上であれば、より使いやすいUIへ変更してよい。

### 3.2 初期版で対象外とする機能

以下の専用ハードウェア連携は、EX v1.0では対象外とする。

- KORG nanoKontrol2
- KORG nanoPAD2
- その他MIDIコントローラー固有対応

将来追加できるよう、入力処理と音声再生処理は分離して設計する。

### 3.3 旧プロジェクト形式

旧「効果音ポンだしくん」の独自バイナリプロジェクトをEXで直接読み込むことは、EX v1.0の必須要件としない。

- 機能互換: 必須
- 旧バイナリプロジェクトのインポート: 将来機能

## 4. 技術スタック

### 4.1 基本構成

- 言語: C#
- ランタイム: .NET 8
- ターゲット: `net8.0-windows`
- GUI: Windows Forms
- JSON: `System.Text.Json`
- 音声処理: NAudioを中心に構成
- Ogg Vorbis: NVorbis / NAudio.Vorbis等のmanaged decoderを同梱
- Ogg Opus: Concentus系のmanaged decoderを同梱
- MP3: OS側コーデックへの依存を避け、managed decoderを同梱することを推奨（例: NLayer系）
- ログ: UTF-8プレーンテキスト
- DB: 使用しない
- ネットワーク機能: 使用しない

### 4.2 配布方式

Self-containedなWindows x64ビルドを標準配布とする。

推奨publish方針:

```text
RuntimeIdentifier: win-x64
SelfContained: true
PublishSingleFile: false
PublishTrimmed: false
```

単一EXE化は必須としない。信頼性・トラブルシュート性を優先し、必要DLLがEXEと同じフォルダに存在する形式でよい。

必要になった場合のみ、別途 `win-x86` ビルドを追加する。

## 5. アプリケーション構成

最低限、以下の責務を分離する。

```text
PondashiEX
├─ UI
│  ├─ MainForm
│  ├─ SoundPanel / SoundCard
│  ├─ TriggerWindow / TriggerPanel
│  └─ SettingsDialog
│
├─ Audio
│  ├─ AudioEngine
│  ├─ SoundInstance
│  ├─ LoopProvider
│  └─ AudioDeviceManager
│
├─ Input
│  ├─ ShortcutManager
│  └─ GlobalKeyboardHook
│
├─ Trigger
│  └─ TriggerEngine
│
├─ Project
│  ├─ ProjectModel
│  ├─ ProjectSerializer
│  └─ ProjectManager
│
└─ Utility
   └─ Logger
```

GUI、音声処理、ショートカット、イベントトリガ、保存処理を相互に直結させない。

すべての操作元は共通のAudioEngine APIを呼び出す。

例:

```text
GUIの再生ボタン ─┐
キーアサイン     ├─> AudioEngine.Play(soundId)
イベントトリガ   ┘
```

同様に停止、一時停止、全停止も共通処理とする。

## 6. 音声エンジン

### 6.1 基本要件

- 複数音源を同時再生可能であること。
- 1つの出力デバイスに対し、内部ミキサーを介して複数音源をミックスする構成を基本とする。
- UIスレッドで重いデコード処理や待機処理を行わないこと。
- 音源の開始・停止・一時停止がUI操作をブロックしないこと。

概念構成:

```text
WAV / MP3 / Ogg Vorbis / Ogg Opus
      ↓
   Decoder
      ↓
 SoundInstance
  ├─ Volume
  ├─ Pan
  ├─ Pitch
  ├─ Loop
  └─ Fade
      ↓
    Mixer
      ↓
 Master Volume
      ↓
 Output Device
```

### 6.2 必須対応形式

最低限以下を対応する。

- WAV
- MP3
- Ogg Vorbis
- Ogg Opus

可能であればOSにインストールされた外部コーデックに依存しない。

その他形式への対応はEX v1.0では必須としない。

### 6.3 音源単位の機能

各音源は最低限以下を保持する。

- 名前
- 音声ファイル
- キーアサイン
- グループ
- 音量
- パン
- ピッチ
- 無限ループ有効/無効
- ループ開始サンプル位置
- Fade In設定
- Fade Out設定
- メモ（任意）

### 6.4 再生操作

各音源に対して以下を行えること。

- 再生
- 停止
- 一時停止
- 再開

同一音源を再度再生した場合の扱いは、実装時に明示して統一すること。

### 6.5 再生状態表示

最低限、以下の状態を視覚的に区別できること。

- 停止中
- 再生中
- 一時停止中
- フェード中

再生中はボタンだけでなく音源パネル全体等でも判別しやすくすることが望ましい。

## 7. 音量・パン・ピッチ・フェード

### 7.1 音量

- 音源ごとの音量調整
- マスター音量調整
- マスターミュート
- 音源ごとの音量とマスター音量を、スライダーと0～100%の数値入力の両方から変更できること

### 7.2 パン

- 左右パン調整
- 右クリック等の簡単な操作で中央へ戻せること

### 7.3 ピッチ

旧UIに存在するPitch機能を維持する。

具体的な倍率範囲・アルゴリズムは、旧ソフトの挙動を確認したうえで決定する。

### 7.4 フェード

- Fade In
- Fade Out
- 音量操作からのフェード
- 通常停止時にFade Outを使用するか、プロジェクト設定で切り替えられること

Fade In／Fade Outは0～60秒の所要時間として指定する。Fadeを有効にした時点で0秒の場合は、操作ミスを防ぐため1.00秒を初期値とする。
停止時フェードが有効な場合、停止ボタン、Shift＋キー、グループ停止、停止トリガは音源ごとのFade Out設定を適用する。無効な場合は即時停止する。「全停止」は緊急操作のため、この設定にかかわらず即時停止する。

---

## 8. ループ

- 無限ループを設定できること。
- ループ開始位置を秒単位で指定できること。
- 0の場合はファイル末尾から先頭へ戻ること。
- 0以外の場合はファイル末尾から指定秒位置へ戻ること。
- 音源長以上の値は先頭として扱うこと。
- 旧プロジェクトのサンプル単位値は互換用として読み込めること。

初回再生は常に先頭から開始し、指定位置は2周目以降に戻る位置として使用する。

---

## 9. キーアサイン

### 9.1 基本仕様

- 任意の音源にキーを割り当てられること。
- 1つのキーに複数音源を割り当て可能であること。
- キー単体: 対象音源を再生
- Shift + キー: 対象音源を停止

### 9.2 フォーカス非依存

本EXで特に重要な要件とする。

**アプリ内のどのUIコントロールにフォーカスが存在しても、キーアサインが正常に動作すること。**

具体的には以下の操作直後でもキーアサインを使用可能であること。

- 音源パネル / 子要素をクリック
- 再生ボタンをクリック
- 停止ボタンをクリック
- 一時停止ボタンをクリック
- 音量スライダーを操作
- パンスライダーを操作
- その他通常UIを操作

特定のフォームやパネルの `KeyDown` に依存する実装は禁止する。

### 9.3 テキスト入力時

音源名、メモ、数値等のテキスト入力中に文字キーのショートカットが暴発しないこと。

テキスト編集コントロールが入力を受けている間は、競合する通常キーアサインを抑制する。

### 9.4 バックグラウンド入力

旧ソフト同様、「バックグラウンド入力許可」を用意する。

- OFF: EXが前面アプリである場合のみキーアサインを受け付ける。
- ON: EXが非アクティブでもキーアサインを受け付ける。

重要: バックグラウンド入力OFFであっても、EX内部のUIフォーカス位置には依存しないこと。

---

## 10. グループ機能

- 各音源にグループを設定できること。
- グループは分類と一括操作に使用し、同じグループ内の複数音源を同時再生できること。
- グループごとの専用ショートカットを複数登録できること。
- グループ専用キーで対象グループを同時再生し、Shift+キーでまとめて停止できること。
- グループを対象とするイベントトリガから、再生・停止・一時停止を一括実行できること。
- グループ未設定音源は通常の独立音源として扱う。
- 音源カードをドラッグして並び替えでき、並び順をプロジェクトへ保存できること。

---

## 11. 全停止

### 11.1 操作経路

最低限以下の3経路から同一の「全停止」処理を呼び出す。

1. GUI上に常時表示された大きめの「全停止」ボタン
2. 「操作」メニュー内の「全停止」
3. キーボードショートカット（旧ソフト準拠でCtrl+Rを初期値とする）

### 11.2 UI要件

- メニューを開かなくても押せること。
- 本番中に見失わない位置へ固定すること。
- 他の操作ボタンより明確に識別できること。
- 誤操作防止のため、通常の音源ボタン群と適度に距離を取ること。

「確認ダイアログを出す」は緊急停止性を損なうため、原則行わない。

## 12. メインUI

### 12.1 基本方針

- 旧ソフトより大きく、舞台音響卓で見やすいUIとする。
- 余計なアニメーション、半透明、3D描画等は使用しない。
- 見た目よりも視認性、反応速度、安定性を優先する。

### 12.2 主な画面領域

最低限以下を1画面内または容易に切り替えられる構成とする。

- 時計 / ストップウォッチ
- マスター音量
- ミュート
- 全停止
- 音源一覧
- イベントトリガ
- 現在の出力デバイス
- 現在のプロジェクト名

ミュートは常設コントロールに加え、「操作」メニューからも同じ状態を切り替えられること。

### 12.3 音源表示

旧ソフトのような「音源1個ごとの小さい子ウィンドウ」をそのまま再現する必要はない。

推奨案は、各音源を大きめのSoundCard / SoundPanelとして表示する方式。

通常表示では本番中によく使う情報を優先する。

- 音源名
- キー
- グループ
- 再生 / 停止 / 一時停止
- 音量
- 再生状態

以下は「詳細」を開いた場合に表示してもよい。

- ファイルパス
- パン
- ピッチ
- Loop
- Loop開始サンプル
- Fade In / Fade Out
- メモ

### 12.4 UIスケーリング

- Windows DPI設定でレイアウトが崩れないこと。
- 少なくとも100%, 125%, 150%, 175%, 200%付近で操作不能にならないこと。
- 可能であればアプリ独自のUI倍率も提供する。

## 13. 時計 / ストップウォッチ

- 通常は現在時刻を表示する。
- 旧ソフト同様、ストップウォッチモードへ切り替え可能とする。
- ストップウォッチには最低限 Start / Reset を用意する。
- モードの違いが色やラベル等で明確に分かること。

ストップウォッチ値はイベントトリガの条件として使用可能とする。

---

## 14. イベントトリガ

### 14.1 イベント項目

各イベントは以下を持つ。

- 有効 / 無効
- メモ
- トリガ条件
- 条件パラメータ
- 実行アクション
- 対象音源

発火後は旧ソフト同様、そのイベントを自動的に無効化する。

### 14.2 トリガ条件

最低限、旧ソフトの以下4種類を実装する。

1. 時刻経過時
2. ストップウォッチの指定時間経過時
3. 指定音源の再生終了時
4. 指定音源の再生開始から指定時間経過時

### 14.3 アクション

最低限以下を実装する。

- 再生
- 停止
- 一時停止

### 14.4 音源参照

旧ソフトは名前で音源を指定するため名前重複に弱い。

EXでは内部的に一意な `soundId` を使って参照し、UI上では名前を表示する。

これにより同名音源が存在しても内部参照を壊さない。

---

## 15. 出力デバイス

- 使用するサウンド出力デバイスを選択可能とする。
- 現在選択中のデバイスを分かりやすく表示する。
- デバイスが切断・消失した場合はクラッシュせず、ユーザーへエラーを表示する。
- 設定したデバイスが見つからない場合は、既定デバイスへのフォールバックを検討する。

## 16. 無音ループ再生

旧ソフトの「無音ループ再生」を維持する。

目的:

古いPCや一部オーディオデバイスで、完全な無音状態から最初の音を鳴らした際に発生する頭切れ・ノイズ等を避ける。

- ON/OFF可能
- 設定はプロジェクトまたはアプリ設定として保存
- ONの場合、可聴音量にならない無音ストリームを継続出力する

## 17. 複数起動・背景色

### 17.1 複数起動

旧ソフト同様、複数インスタンスの同時起動を禁止しない。

### 17.2 背景色

複数シーンや複数インスタンスを視覚的に区別できるよう、メイン画面の背景色またはテーマ色をプロジェクト単位で変更可能とする。

## 18. プロジェクト形式

### 18.1 基本仕様

- 内容: UTF-8 JSON
- 拡張子: `.pondex`（仮）
- 人間がテキストエディタで直接確認・編集できること。
- 独自バイナリ形式を使用しないこと。
- YAMLは採用しない。

### 18.2 バージョン

ルートに必ず以下を持つ。

```json
{
  "formatVersion": 1
}
```

将来の仕様変更時にマイグレーションできるようにする。

未知の追加フィールドが存在しても、可能な限り読み込みを継続する。

### 18.3 JSON例

```json
{
  "formatVersion": 1,
  "project": {
    "name": "聖夜に少女は夢を見る",
    "themeColor": "#202020"
  },
  "settings": {
    "outputDevice": "default",
    "masterVolume": 1.0,
    "silentLoop": false,
    "backgroundInput": false
  },
  "sounds": [
    {
      "id": "b734ad00-71d1-4d52-9d54-000000000001",
      "name": "ドアを閉める",
      "file": "sounds/door.wav",
      "key": "A",
      "group": "SE-A",
      "volume": 0.8,
      "pan": 0.0,
      "pitch": 1.0,
      "loop": {
        "enabled": false,
        "startSample": 0
      },
      "fadeIn": {
        "enabled": false,
        "value": 0.0
      },
      "fadeOut": {
        "enabled": true,
        "value": -6.0
      },
      "memo": ""
    }
  ],
  "triggers": []
}
```

Fade値の単位は旧ソフト挙動確認後に正式決定する。

### 18.4 パス

- プロジェクトファイルからの相対パスを優先する。
- JSON内では `/` 区切りを標準とする。
- 読み込み時にOS用パスへ正規化する。
- 必要な場合のみ絶対パスを許容する。

推奨構成:

```text
ProjectFolder/
├─ show.pondex
└─ sounds/
   ├─ bgm01.ogg
   ├─ door.wav
   └─ bell.mp3
```

このフォルダを丸ごと移動しても音源を見失わないことを目標とする。

## 19. プロジェクト操作

最低限以下を実装する。

- 新規作成
- 開く
- 保存
- 名前を付けて保存
- 最近使ったプロジェクト（最大10件）

音源追加前に必ず一度プロジェクト保存を要求する、という旧ソフトの制限は継承しなくてよい。

### 19.1 安全な保存

保存時に既存ファイルへ直接書き込まない。

例:

```text
show.pondex
   ↓ 保存開始
show.pondex.tmp
   ↓ 正常に書き込み・検証完了
show.pondex を置換
```

さらに1世代バックアップを残す。

```text
show.pondex.bak
```

保存途中の電源断や異常終了で本体ファイルを破損しにくい方式とする。

- ドラッグ&ドロップで追加可能
- 複数ファイルの一括追加を可能とすることが望ましい

## 21. エラー処理

舞台本番用途のため、可能な限り1件の異常でアプリ全体を終了させない。

例:

- 音源ファイルが見つからない
- 音源ファイルが壊れている
- 未対応フォーマット
- 出力デバイスが存在しない
- JSONの一部が不正

この場合、対象項目を分かりやすくエラー表示し、他の正常な音源は可能な限り使用可能にする。

致命的なプロジェクトJSONエラーの場合は、行・項目等の情報を可能な範囲で表示する。

---

## 22. ログ

- `Logs/` 以下へUTF-8テキストログを出力可能とする。
- 通常時に大量のログを書き続けない。
- 起動、プロジェクト読込、保存、音声デバイス異常、デコード失敗、例外等を記録する。
- ログ機能が音声再生をブロックしないこと。

---

## 23. 性能・安定性要件

- 待機中に継続的な高CPU負荷を発生させない。
- 数十～数百音源を登録してもUI操作に大きな遅延を発生させない。
- 音源再生操作に対する反応は、人間が本番中に「遅い」と感じないことを目標とする。
- 長時間起動してもメモリリークやハンドルリークを発生させない。
- 音声再生中にプロジェクトを切り替える場合、既存音声を確実に停止してから切り替える。
- UIの描画やJSON保存によって再生中音声が途切れないこと。

## 25. 受け入れ条件（EX v1.0）

最低限、以下を満たした場合にEX v1.0の基本完成とする。

1. 対象の古いWindows 10音響PCで、追加インストールなしに起動できる。
2. WAV / MP3 / Ogg Vorbis / Ogg Opusを登録・再生できる。
3. 複数音源を同時に再生できる。
4. 再生・停止・一時停止がGUIから行える。
5. 音量、パン、ピッチ、ループ、ループ開始点、フェード、グループが動作する。
6. キーアサインで再生でき、Shift+キーで停止できる。
   グループ専用ショートカットでも、グループ全体の同時再生と停止ができる。
7. 音源UIや停止ボタン等をクリックした直後でもキーアサインが効く。
8. バックグラウンド入力ON/OFFが動作する。
9. GUI上の常設「全停止」ボタンから即時に全音源を停止できる。
10. Ctrl+Rおよび操作メニューからも同じ全停止処理を呼び出せる。
11. 操作メニューからマスターミュートを切り替えられる。
12. 通常停止時にFade Outを使うか設定で切り替えられる。
13. 時計 / ストップウォッチが動作する。
14. 4種類のイベントトリガと3種類のアクションが動作する。
15. 出力デバイスを選択できる。
16. 無音ループ再生をON/OFFできる。
17. JSON `.pondex` 形式で保存・読み込みできる。
18. プロジェクトとsoundsフォルダを別PCへコピーしても相対パスで再利用できる。
19. 壊れた音源や欠落ファイルがあっても、可能な限り他の音源を操作できる。
20. DPI拡大環境でも主要UIが崩れない。
19. 長時間起動・連続操作でクラッシュしない。

## 26. Codex実装時の注意

- まずAudioEngineを単体で成立させ、その後UIを接続する。
- UIイベント内に音声処理本体を書かない。
- 個別フォームのKeyDownへキーアサインを直書きしない。
- `soundId` を内部参照の基準とし、表示名をID代わりに使用しない。
- ファイルIO・デコード失敗を未処理例外として放置しない。
- 保存はtmp + replace + bak方式を使用する。
- JSONモデルには `formatVersion` を必須とする。
- インターネットアクセスを実装しない。
- テレメトリを実装しない。
- レジストリ依存を作らない。
- 不必要な外部依存を増やさない。
- 依存パッケージはライセンスを確認し、配布物に必要なライセンス表記を同梱する。
- 「軽量・確実・本番中に迷わない」を優先し、不要なアニメーションや装飾を追加しない。

## 27. 実装前に実機確認したい項目

旧ソフトとの差異を確認しつつ、EXでは操作の明確さと安定性を優先して以下を継続確認する。

- Fade In / Fade Out の実音上の立ち上がり・減衰特性
- Volume右クリックフェードの操作性
- Pitch処理の音質
- グループ専用ショートカットによる複数音源の同時再生・停止
- 同一音源を再度再生した場合の挙動
- 一時停止後に再生操作した場合の挙動
- 「全停止」が一時停止音源を含めどの状態まで完全リセットするか
- 無音ループ再生の実際の方式
- 出力デバイス変更時の再生中音源の扱い

これらは「旧ソフトと同じ挙動を再現する」か「EXとして改善する」かを確認後に確定する。

## 28. 設計思想まとめ

効果音ポン出しくんEXは、一般的な音楽プレイヤーではなく舞台本番用のポン出しソフトとして設計する。

優先順位は以下とする。

```text
1. 確実に鳴る / 止まる
2. 操作不能にならない
3. 本番中に一目で状態が分かる
4. 古いPCでも軽い
5. 完全オフラインで動く
6. プロジェクトを人間が直接読めて救出できる
7. 見た目
```
